# Updater implementation notes

Implementation in progress, 2026-10-11. The reviewed contract is [UPDATER-SPEC.md](UPDATER-SPEC.md).

`UpdateController` owns Sparkle 2.10's custom user driver and native scheduled checks. A background offer receives its reply immediately. A user click checks native readiness, commits pending edits and acquires AppModel's main-actor work latch before starting a fresh interactive check. Privacy and automatic-download controls are explicit. Unsupported/information-only/major/package/remote-HTTP items are rejected. A loopback HTTP asset is permitted only in a compiled validation fixture.

AppModel's `updateBlockingWork`, `canBeginUpdate`, `acquireUpdateLock`, `updateSafePoint` and `releaseUpdateLock` provide the shared gate. Capture phases, formatting, tracked import and independent summary tasks, pending paste, credential verification and file dialogs block eligibility. Title drafts are staged at the binding boundary; pending-edit flushes acknowledge durable saves. Commands and editable content respect the acquired latch, while sidebar navigation and record selection remain available.

The ready-to-install callback uses a fresh saved-edit/idle gate and responds Skip when it fails. An unexpected background staged installer also receives Skip. If the final native quit is denied, the same Reintentar button retains the work latch and retries only Sparkle’s termination handler after another saved-edit gate. Genuine cycle completion/abort clears the handler and latch, including a nil-error relaunch veto. The driver uses short Spanish stages and actual bounded download progress in a fixed 148 × 32 Circles/Urbanist control. Reduced Motion removes indefinite animation. Accessibility announcements occur at stage transitions, never per downloaded byte. Failure feedback stays in the updater control.

`UpdateResumeStore` atomically writes navigation metadata only: sidebar, selected record UUID, window visibility, target build and time. Its one-shot consumer validates build, known sidebar, UUID decoding and a ten-minute validity window. AppDelegate restores through the shared library-window path. Ordinary Open Transcribe still resets Dictation, and ordinary keyed startup remains menu-bar-only.

Validation fixtures are compiled separately with `TRANSCRIBE_VALIDATION_FIXTURE`. AppDelegate uses a core-owned isolated model factory, skips shortcuts/permission refresh/chips and opens its own library window. The plist supplies a unique fixture bundle identity and private temporary support root. Production bootstrap is unchanged. Package/framework/helper signing and the production feed are owned by the packaging/release task.

Offline test runner: `TranscribeBar/scripts/test-updater.sh`. It supplies a fake check transport and fake coordinator operations and writes only isolated synthetic fixture data. It never launches the app, requests audio/ASR, reads credentials, accesses the clipboard or sends HTTP requests. Production full-source typecheck against Sparkle 2.10 and 30 offline updater checks passed. The checks include failed notes/summary drafts, final-install Skip, nil-error abort and explicit denied-quit recovery. The runner uses synthetic appcast parsing; it does not validate OS-dependent appcast compatibility. Fixture-build typecheck and signed installer/relaunch validation remain pending final integration. Passing offline fixtures alone does not establish helper installation or relaunch reliability.
